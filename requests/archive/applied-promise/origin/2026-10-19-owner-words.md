## Problem

`promise-kind` fires for any changed paragraph of a non-promise kind whose text holds MUST, SHALL, SHOULD, MAY, never or always. A flow step that applies a rule stated in a rule paragraph is a common case: for example, a flow step "a machine event never does [start a run]" that applies a rule paragraph saying that only a person's comment starts a run. The hint then asks to reclassify a flow that is correctly a flow, and it returns each time the paragraph changes.

There is no way to record the answer, so the only ways to silence it are rewording the text to avoid the keyword or changing the kind.

## Request

Let the author record that the words apply an existing promise, for example a link from the paragraph to the promise paragraph it applies (`governed-by`, `builds-on`, or a dedicated link), and give no `promise-kind` hint when such a link exists.
