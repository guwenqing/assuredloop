Own ordinary execution and arrange the independent test/review work directly within the assigned authority. ## Verify and implement

For executable work the action order is: independent test author, observed behavioral RED, corresponding implementation, the same tests GREEN, relevant controlled faults, restoration/recheck, and independent review. Do not put implementation before the failing-test step in the concrete handoff plan.

For executable work, the independent test author is a separate subagent managed directly by the implementation owner, not a permanent tester bot, another work Issue, or a coordinator-mediated handoff. The owner invokes that subagent and receives its output directly. Give it original requirements and observable cases, not the implementation as an oracle; the subagent must not implement the product change it tests. Run applicable tests before the corresponding implementation; inspect and record a genuine failure caused by the missing/wrong behavior. Tool/setup failures are not behavioral RED.

Implement the smallest coherent change, then rerun the same tests to GREEN. Do not disable assertions or adjust expectations to fit faulty code. An incorrect test returns to its independent author with the requirement evidence. Use relevant controlled product-code/input faults to check detection, record their meaning and limits, restore all deliberate faults and rerun the applicable checks. A surviving non-equivalent fault is a verification gap to resolve. Non-executable work instead receives suitable artifact checks and independent semantic review.

Keep full logs outside tracked source. Native tasks.md marks describe candidate contributions, not approval or merged delivery. Do not mark future merge, post-merge verification or Issue closure as already done.

## Review, integrate and complete

Obtain a different eligible agent/session's full-scope internal review under accepted project.review rules. Exclusions and resolved aliases apply; no guessed vendor tiers or self-acceptance. Supply original basis, actual changes, negative cases, tests/fault evidence and limitations. Use an additional/external reviewer when required or explicitly requested. Missing/interrupted reports and stale results remain incomplete.

Resolve accepted `project.review.routing` before assigning reviews. Primary/internal evidence declares the selected `primary_tool`; required additional/external evidence may use any supported native tool ID, with no installation requirement. Both declare actual kind/tool/model and distinct eligible sessions for the exact candidate. The same model/tool can supply separate assessments; the producer and a reused reviewer session cannot satisfy independence. When `additional` is `required`, collect both qualifying source records; additional evidence never replaces primary. For `on-request`, preserve any explicit additional request and its source in the work handoff and obtain its actual disposition. That manual obligation does not create a permanent second gate. Legacy routing-absent policy stays unchanged; candidate routing cannot authorize its own adoption.

Create/update the Issue-linked work PR with the authoritative Workflow context and actual evidence. Resolve findings or obtain an explicit accepted disposition; discuss evidence with the reviewer and return material disagreements to the responsible owner. New content or material head/base/policy/work-context changes require renewed applicable assessment. Never transfer an old PASS silently.

After checks/reviews and the actual required approvals cover the exact candidate/destination, perform authorized submission/merge without inventing another approval category. Respect protections and explicit owner holds. Recheck freshness immediately before integration and verify the real merge/squash commit and assigned outcome afterwards. Staging acceptance proves only its assigned staging scope; final integration needs its own assessment.

Record delivery evidence and close the Issue only when its whole assigned scope is delivered. Partial PR contributions leave it open. Do not close the parent or perform unassigned synchronization/archive. Return the result and remaining limits only where the current handoff explicitly assigns delivery tracking or requires that return; the architect or assignment author is not a default completion recipient.
